# 데이터 전처리 담당 작업 정리 (2026-10-12 ~ 10-15)

Tor 웹사이트 핑거프린팅(WF) 프로젝트에서 데이터 전처리 담당이 한 일을 처음부터 끝까지 정리한 문서다. 팀원(특히 모델 담당)이 이 문서 하나로 지금까지의 작업, 결과, 넘겨받을 것, 남은 결정을 파악할 수 있도록 썼다.

| 핵심 결과 | 기록 **앞부분의 방향 패턴**(처음 N셀 중 송신 수, 앞쪽 버스트 길이 순서)을 피처로 추가해 정확도가 크게 올랐다. RF 기준 87.9% → **95.5%** (train 내부 교차검증, 기본 하이퍼파라미터) |

| 발견한 문제 | 마지막 방문(inst 19)의 기록이 다른 방문보다 짧고 느리다. 현재 test 분할(inst 18~19)은 정확도가 낮게 나온다 → **팀 결정 필요** |

**"모델 선택"이 아니라 "모델을 도구로 쓴 피처 검증"이다.** 모든 모델을 기본 하이퍼파라미터로 고정하고 피처만 바꿨다. 그래서 아래 표의 모델별 점수는 모델 순위로 해석하면 안 된다.

## 1. 데이터 이해

### 1.1 데이터 구성
| 파일 | 내용 |
|---|---|
| `mon_standard.pkl` | 감시 대상 사이트 95개 × URL 10개 × 방문 20회 = **19,000개**. 사이트당 200개, 클래스 불균형 없음 |
| `unmon_standard10.pkl` | 감시 대상이 아닌 사이트 **10,000개**, 라벨 없음 (open-world용) |
| `unmon_standard10_3000.pkl` | 위 파일의 앞 3,000개와 완전히 같다 (확인함). 빠른 실험용 |

- 기록 하나는 숫자 리스트이고, 숫자 하나가 Tor 셀(512바이트) 하나다.
- 절댓값 = 첫 셀 기준 시각(초), 부호 = 방향(+ 송신, − 수신).
- 라벨 = URL 번호 // 10 (사이트 번호 0~94).

### 1.2 팀 공통 규칙 정리
교수님이 제공한 `load_pickle_code.ipynb`와 같은 규칙으로 데이터를 읽는 공용 로더 `code/load_data.py`를 만들었다. **팀 전원이 이 파일로 읽으면 라벨·방향 규칙이 어긋나지 않는다.**

| 항목 | 규칙 |
|---|---|
| 라벨 | `i // 10` (사이트 95개) |
| 방향 | `c > 0`이면 +1(송신), 아니면 −1(수신) |
| 시간 | `abs(c)` |
| 크기 | 방향 × 512 |

- 첫 값 `0.0`은 부호로 방향을 알 수 없다. 규칙상 수신(−1)으로 처리하고, 강의 슬라이드 예시와도 일치한다.
- 처음에는 `+0.0`을 송신으로 처리했다가 노트북과 달라서 수정했다(10/13). 그 결과 모든 기록에서 송신 수가 1 줄었고 정확도 변화는 ±0.3%p 이내였다.
- **29,000개 기록 전부를 노트북 코드와 비교해 불일치 0개**를 확인했다.

### 1.3 품질 점검 (`code/check_data.py`)
| 점검 | 결과 |
|---|---|
| 빈 기록, NaN, 무한대 | 없음 |
| 시간 역행 | 없음 |
| 0.01초 단위에서 벗어난 값 | 없음 |
| 길이 | 50~9,993셀. **약 10,000에서 잘린 것으로 보임** (9,900셀대: mon 11.6%, unmon 17.9%). 50 미만은 없음 |
| 시간 해상도 | 0.01초. 직전 셀과 시각이 같은 비율 **약 93%** → 시간 정보가 거칠다 |

### 1.4 기본 통계 (`code/explore.py`)
| 항목 | mon | unmon |
|---|---|---|
| 길이 중앙값 | 3,309 | 4,193 |
| 지속 시간 중앙값 | 26.0초 | 18.9초 |
| 송신 비율 중앙값 | 9.0% | 7.9% |

- 웹페이지를 내려받는 과정이라 대부분 수신이다.
- **mon과 unmon은 분포가 다르다**(unmon이 더 길고 더 빨리 끝남). 수집 환경이 달랐을 수 있으므로 open-world에서 모델이 사이트 특징 대신 환경 차이를 배울 위험이 있다.

## 3. 피처 분석: 어떤 피처가 중요한가

### 3.1 피처 하나씩 보기 (η², 상관관계)
- η²(피처 하나로 사이트가 얼마나 갈리는지) 상위 20개가 **서로 상관 0.9 이상**이었다. 사실상 "기록 길이"라는 같은 정보다.
- 그래서 η² 상위 20개로만 분류하면 하위 20개보다 정확도가 **낮았다**(9.7% vs 15.3%, 아주 단순한 분류기 기준). → 피처를 하나씩만 보고 고르면 안 된다.
- `in_burst_1~3`은 η²가 0이었다(모든 기록이 같은 패턴으로 시작).
- 처음에는 η²를 test까지 포함해 계산하는 데이터 누수가 있었다. 발견해서 train으로만 계산하도록 고쳤다.

### 3.2 모델 기준 중요도 (`code/feature_importance.py`, 랜덤 포레스트)
피처끼리 정보가 겹치는 것까지 반영해 다시 봤다.
- **기록 길이 계열 17개**: 묶음째 섞으면 정확도 −51.7%p로 가장 중요하지만, 하나씩 섞으면 각 0.5%p 안팎이다. 서로 대신한다.
- **단일 피처 1~3위**: `first30_out`(−5.0%p), `first100_out`(−3.5%p), `cumul_at_500`(−2.7%p). 모두 **기록 앞부분**의 정보다.
- **시간 피처 18개**: RF에서는 빼도 정확도가 그대로였다.
- **mon vs unmon 구분**: AUC 0.968. 시간 피처가 상위권이라 수집 환경 차이를 배운 것일 수 있다.
- **한계**: permutation 중요도를 test로 계산했다. 가설을 만드는 데만 썼고 평가는 이후 CV로 했지만, 엄밀하게는 train 안에서 다시 계산해야 한다.

### 3.3 데이터 이상 발견: 마지막 방문(inst 19)
방문 2개씩 test로 빼서 정확도를 재면 **어느 2개를 빼도 87~90%인데, 18~19만 73%** 였다.

| | inst 0~17 | inst 18 | inst 19 |
|---|---|---|---|
| 길이 중앙값 | 약 3,300~3,500 | 3,184 | **2,340** |
| 지속 시간 중앙값 | 약 22~26초 | 29.9초 | **40.7초** |
| 초당 셀 수 | 약 124~131 | 117 | **76** |
| RF 정확도 | - | 82.2% | **63.7%** |

- inst 19는 네트워크가 느렸거나 로딩이 덜 끝난 기록이 많은 것으로 보인다(수집 코드가 없어 확정 불가).
- 현재 test(inst 18~19)는 **일반 방문보다 어려운 세트**다. 초기 보고값(RF test 73%)은 낮게 나온 값이다.
- 앞부분 피처(`first30_out` 등)는 inst 19에서도 값이 같다. 기록이 덜 끝나도 앞부분은 영향을 받지 않는다.

## 4. 피처 검증 실험 (모델을 도구로 사용)

### 4.1 실험 규칙 (실험 전에 정함)
| 항목 | 내용 |
|---|---|
| 평가 | **train(17,100개) 내부 5-fold 교차검증**. fold = 방문 번호 % 5. **test는 쓰지 않았다** |
| 판단 기준 | 기준 조합 대비 차이가 **1%p(≈ fold 간 표준편차) 이내면 같은 수준**, 피처가 적은 쪽을 고른다 |
| 모델 | 수업에서 다룬 모델(LR, NB, SVM, DT, RF, ET, k-NN, MLP), **기본 하이퍼파라미터 고정** |
| 전처리 | 트리 모델은 원본 값, 나머지는 `sign(x)·log(1+|x|)` 후 표준화 (학습 fold 기준) |

- **test를 쓰지 않은 이유**: test 점수를 보면서 피처를 바꾸면 test에 우연히 맞는 조합을 고르게 된다.
- **여러 모델에 같은 조합을 돌린 이유**: 피처 효과가 모델마다 다르다. 트리 모델은 쓸모없는 피처에 둔감하고, SVM·k-NN·LR은 민감하다.

### 4.2 1단계: 기준점 (기존 55개 전체)
| RF | ET | SVM | MLP | k-NN | DT | LR | NB |
|---|---|---|---|---|---|---|---|
| 87.9 | 87.7 | 82.0 | 78.8 | 74.9 | 69.3 | 59.6 | 24.6 |

- NB는 상관 높은 피처가 많아 독립 가정이 맞지 않는다.
- MLP는 한 번에 12분~1시간 이상 걸려 이후 단계에서 뺐다.

### 4.3 2단계: 빼도 되는 피처가 있나 (기준 B = 상수 3개 제거, 52개)
| 조합 | LR | k-NN | RF | ET | SVM | 결정 |
|---|---|---|---|---|---|---|
| B: 상수 3개 제거 | 59.7 | 74.9 | 87.9 | 87.9 | 82.1 | **채택** |
| B − 시간 그룹 | −9.1 | −0.2 | −0.8 | −0.9 | −4.3 | 기각 (SVM·LR 손해) |
| B, 길이 계열 → 1개 | −2.3 | −2.0 | −1.1 | −1.3 | −0.3 | 기각 |
| 둘 다 | −12.7 | −2.9 | −1.8 | −1.0 | −4.2 | 기각 |

- "시간 피처는 겹친다"는 가설은 **트리 모델에서만 성립**했다. RF 분석 하나로 결론 내리지 않고 여러 모델로 확인한 이유다.
- **피처를 빼서는 정확도가 오르지 않았다.** 기존 피처로는 약 88%가 한계 → 새 정보가 필요하다.

### 4.4 3단계: 새 피처를 더하면 좋아지나 (B에 추가)
| 추가 | 개수 | LR | k-NN | RF | ET | SVM |
|---|---|---|---|---|---|---|
| (B) | 0 | 59.7 | 74.9 | 87.9 | 87.9 | 82.1 |
| @early | 7 | 72.4 | 85.0 | 92.4 | 92.2 | 90.7 |
| @cumulabs | 13 | 66.2 | 78.6 | 90.7 | 90.9 | 85.7 |
| **@bseq** | 27 | 78.9 | 82.1 | **94.3** | 93.3 | 91.2 |
| @cumul100 | 100 | 64.9 | 77.3 | 88.4 | 87.4 | 81.1 |
| 전부 (@extra) | 147 | 86.4 | 85.7 | 95.0 | 93.1 | 92.8 |

- @early, @bseq, @cumulabs는 **모든 모델에서** 정확도를 올렸다.
- @cumul100(100개)은 트리 모델과 SVM에서 효과가 없었다.
- CUMUL 논문 방식을 흉내 낸 조합(개수 + 누적합 100지점)은 SVM 51.4%로 낮았다. 논문처럼 튜닝하지 않았으므로 **논문 재현으로 보면 안 된다.**

### 4.5 3b단계: 효과 없는 피처를 빼고 최종 후보 정하기
| 조합 | 개수 | LR | k-NN | RF | ET | SVM |
|---|---|---|---|---|---|---|
| B + @extra | 199 | 86.4 | 85.7 | 95.0 | 93.1 | 92.8 |
| **B + @early + @bseq** | **86** | 83.4 | 84.8 | **95.5** | **95.0** | **93.1** |
| B + @early + @bseq + @cumulabs | 99 | 85.0 | 85.2 | 95.7 | 95.2 | 93.1 |

- @cumul100을 빼니 피처가 199개에서 86개로 줄었는데 RF·ET·SVM은 같거나 올랐다.
- @cumulabs를 더한 99개는 LR에서만 +1.6%p다. 나머지는 1%p 이내라 판단 기준상 86개를 골랐다.

### 4.6 4단계: 앞부분 패턴을 더 늘리면 좋아지나 (C = 3b단계 후보 86개에 추가)
| 조합 | 개수 | LR | k-NN | RF | ET | SVM | 결정 |
|---|---|---|---|---|---|---|---|
| C | 86 | 83.4 | 84.8 | 95.5 | 95.0 | 93.1 | |
| C + @bseqlong | 156 | −4.7 | −7.2 | −0.5 | −0.7 | −3.1 | 기각 |
| **C + @dir50** | **131** | **+5.8** | **+5.4** | −0.1 | +0.3 | **+1.7** | **채택** |
| C + @dir | 181 | +4.4 | +3.2 | +0.1 | +0.6 | +1.0 | @dir50보다 낮음 |
| C + @bseqlong + @dir | 251 | +3.1 | +2.2 | −0.2 | +0.4 | +0.8 | 기각 |

- 30번째 이후 버스트는 잡음에 가깝다. 처음 50셀의 방향값은 k-NN·SVM·LR에 도움이 된다.
- **RF 최고 정확도는 오르지 않았다**(95.4~95.6%, 오차 범위 안). 요약 피처로 RF를 더 올리기는 어렵다. 남은 방법은 하이퍼파라미터 튜닝이나 시퀀스 모델이다.

### 4.8 4b단계: 후보 안에 정보 없는 피처가 섞여 있지 않나

그룹 단위로만 넣고 뺐기 때문에 그룹 안의 개별 피처는 점검하지 않았다. train만 써서 다시 봤다(자세한 내용은 [EXPERIMENTS.md](EXPERIMENTS.md) 4b단계).

| 발견 | 내용 |
|---|---|
| **준상수 13개** | `first10_out`, `bseq_4~6`, `dir_006~014`. 한 값이 **99.98% 이상**, train-only η² 0.0054(우연 수준 0.005). 모든 기록이 처음 14셀까지 같게 시작한다 |
| 빼도 손해 없음 | 131 → **118개**. k-NN 소수점 4자리까지 동일(0.9022), RF −0.03%p(노이즈). RF는 **1.6배 빠르다** |
| **개수는 확정적이지 않다** | RF 시드 3개 반복(시드 변동폭 최대 0.09%p): `@cumulabs` 쪽 95.75% > C 95.51% > 후보 95.39%. **시드 3개 전부 같은 순서**다. 피처 개수는 정답이 아니라 탐색 경로의 산물이다 |
| **open-world 경고** | 같은 13개가 unmon에서는 값이 변하고(일부는 다른 상수: `bseq_6` mon 2 / unmon 1, `dir_008` mon +1 / unmon −1), **이 13개만으로 mon/unmon을 AUC 0.9999로 가른다**. 사이트 구분력이 0인 피처가 그렇다는 것은 수집 환경 차이를 배운다는 뜻으로 보인다 |

**조치**: `experiment.py`의 `@early`·`@bseq`·`@dir50`·`@dir`에서 13개를 제외했다. 삭제하지 않고 **`@qconst` 그룹으로 남겼다** — open-world는 과제가 다르니 피처셋을 따로 정하면 되고, 쓸지 말지를 의식적으로 결정하도록 이름을 남겼다. 이전 로그의 피처 수를 재현하려면 명령 맨 뒤에 `@qconst`를 붙인다.

**재현되는 것과 아닌 것**: **88% → 95%(앞부분 방향 패턴)는 노이즈의 15배로 확실하다.** 95.4 vs 95.7 중 무엇이 최고인지는 이 노이즈 수준에서 정하기 어렵다. 86 / 99 / 118 / 131 / 181이 모두 95.4~95.7% 안에 있다.

### 4.9 결론
- **후보 피처셋: 118개** (기존 55개 − `in_burst_1~3` + `@early` + `@bseq` + `@dir50`, 준상수 13개 제외). 최종 모델이 RF·ET라면 `@dir50`을 뺀 82개로도 같은 수준이고, RF만 보면 `@cumulabs`를 더한 쪽이 0.3%p 높다
- **단일 공통 피처셋을 먼저 확정하려는 전제를 버렸다.** 모델이 정해진 뒤 모델별로 피처셋을 정하는 순서가 맞다 (4b단계)
- 사이트 정보는 **기록 앞부분의 방향 패턴**에 가장 많다. 페이지 로딩 초반에 어떤 순서로 요청하고 받는지가 사이트마다 다르기 때문으로 보인다.
- 시간 피처는 트리 모델에는 불필요하지만 SVM·LR에는 필요하다 → **모델별로 다르게 쓴다.**

## 6. 모델 담당에게 넘기는 것

### 6.1 바로 쓸 수 있는 것
```
pip install -r requirements.txt
python -I -X utf8 code/experiment.py --list                                   # 피처·그룹·모델 목록
python -I -X utf8 code/experiment.py @all -@const @early @bseq @dir50 -m rf    # 후보 피처셋 118개
python -I -X utf8 code/experiment.py @all -@const @early @bseq @dir50 -m svm -p C=100 -p gamma=0.01
```
- PowerShell에서는 `@`가 splat 연산자라 따옴표가 필요하다: `'@all' '-@const' '@early' ...`
- 4b단계 이후 그룹 정의가 바뀌었다. `logs/stage*.log`의 피처 수(131 등)를 재현하려면 맨 뒤에 `@qconst`를 붙인다.
노트북에서:
```python
import sys; sys.path.insert(0, 'code')
from experiment import run
r = run(['@all', '-@const', '@early', '@bseq', '@dir50'], model='rf', n_estimators=500)
```
- 기본은 train 내부 5-fold CV다. `--test`는 최종 1회만 쓴다.
- 결과는 `logs/experiments.csv`에 쌓인다(개인 기록, git 제외).

### 6.2 지켜야 할 것
1. **test(inst 18~19)는 마지막에 한 번만** 쓴다. 튜닝과 모델 비교는 CV로 한다.
2. 모델별 전처리가 다르다. 트리 모델은 원본 값, SVM·k-NN·LR은 log 변환 후 표준화(`experiment.py`가 자동으로 처리).
3. 지금의 모델별 점수는 **기본 하이퍼파라미터 결과**라 모델 순위가 아니다.
4. CV 점수와 test 점수를 직접 비교하지 않는다(inst 19 문제).

### 6.3 모델 담당이 할 일 (제안)
- 후보 피처셋(118개)으로 RF, ET, SVM 등 하이퍼파라미터 튜닝 (train 내부 CV)
- 모델 선택과 근거 정리 (제안서 "쓸 모델과 이유")
- **모델별로 피처셋을 다르게 두는 것을 기본으로 한다** (4b단계). 단일 공통 피처셋이 하나로 존재한다는 전제는 데이터가 지지하지 않는다
  - RF·ET: `@dir50` 없이 82개로도 같은 수준. `@cumulabs`를 더하면 시드 3개 모두에서 0.3%p 높다
  - SVM·k-NN·LR: `@dir50`이 +1.7~5.8%p로 필요하다. LR은 `@cumulabs` 추가 시 +1.6%p
- 피처셋 비교는 **시드를 2~3개 돌려서** 본다. 시드 변동폭이 최대 0.09%p로 작아 0.3%p 차이도 구분된다. fold 간 표준편차(0.4%p) 기준의 1%p 규칙은 짝지은 비교에는 둔하다

## 9. 한계

- 분할 1개, 시드 1개 결과다. fold 간 표준편차가 0.3~1.3%p이므로 1%p 이내 차이는 의미 없다.
- 피처 조합은 가설에 따라 손으로 고른 것이다. 모든 조합을 탐색하지는 않았다.
- 피처 선택과 평가를 같은 CV로 했다. 여러 조합 중 가장 좋은 것을 골랐으므로 후보 피처셋의 CV 점수는 약간 낙관적이다. 최종 test 1회로 확인해야 한다.
- 길이가 약 10,000에서 잘린 이유, inst 19가 다른 이유는 수집 코드가 없어 확정할 수 없다.
