# 데이터 전처리 작업 정리

Tor 웹사이트 핑거프린팅(WF) 프로젝트에서 **데이터 전처리 담당**이 만든 작업 베이스예요. 데이터를 읽고, 데이터를 점검하고, 피처를 뽑고, 그 피처가 쓸모 있는지 간단히 확인하는 것까지 들어 있어요.

- 데이터가 어떻게 생겼는지 → [DATA.md](DATA.md)
- 피처 55개가 각각 무엇인지 → [FEATURES.md](FEATURES.md)

## 폴더 구조와 파일별 역할

### ① `code/load_data.py`: 공용 데이터 로더 (**팀 전원이 이걸로 읽기**)
교수님이 주신 `load_pickle_code.ipynb`와 **같은 규칙**으로 pkl을 읽어요.
- 라벨 `i // 10` (사이트 95개), 방향 `c > 0`이면 송신(+1) 아니면 수신(-1), 시간 `abs(c)`, 크기는 방향 × 512
- `load_mon(경로)` → 노트북과 같은 `X1`(시간), `X2`(방향×512), `y`(라벨)
- `load_unmon(경로)` → `X1`, `X2`
- `iter_mon(경로)` → 기록을 하나씩 돌려줘서 메모리를 덜 써요. URL 번호와 방문 순번(inst)도 같이 줘요.

```python
import sys; sys.path.insert(0, 'code')
import load_data as ld
X1, X2, y = ld.load_mon('C:/Users/user/Downloads')
```

### ② `code/check_data.py`: 데이터 품질 점검
빈 기록, NaN, 시간이 거꾸로 가는지, 길이 상한, 0.01초 단위인지 등을 확인해요. 그리고 **`load_data.py`가 교수님 노트북 코드와 똑같은 결과를 내는지** 29,000개 기록 전부를 비교해요(현재 다른 기록 0개).

### ③ `code/explore.py`: 기본 통계
길이 분위수, 지속 시간, 송신 비율을 mon과 unmon 따로 출력해요. [DATA.md](DATA.md) 3절의 표가 여기서 나왔어요.

### ④ `code/features.py`: 피처 추출 + 분석
1. 기록마다 피처 55개를 뽑아 CSV 2개로 저장해요. **다른 팀원이 모델을 학습할 때 쓰는 결과물이 이거예요.**
2. 피처마다 사이트를 잘 가르는지(η²), mon과 unmon을 잘 가르는지(AUC)를 계산해요.
3. 서로 거의 같은 정보를 담은 피처 쌍(상관계수 0.9 초과)을 찾아요.
4. 간단한 분류기(⑤와 같은 것)로 정확도를 출력해요.

### ⑤ `code/eval_nearest_centroid.py`: 피처가 쓸모 있는지 평가
④가 저장한 CSV를 읽어서 아주 단순한 분류기로 정확도를 재요. **최종 모델이 아니라** "이 피처들로 사이트를 구분할 수 있긴 한가?"를 빠르게 확인하는 용도예요.
- **분류기 (nearest centroid)**: train 데이터로 사이트마다 피처 평균점을 구하고, test 기록을 가장 가까운 평균점의 사이트로 예측해요.
- **분할**: URL마다 방문 20회 중 0~17번째는 train(17,100개), 18~19번째는 test(1,900개). 무작위 요소가 없어요.
- **전처리**: `sign(x)·log(1+|x|)`로 값의 크기를 줄인 다음, train의 평균과 표준편차로 표준화해요.
- ④와 다른 점: 피처를 고를 때 η²를 **train으로만** 계산해요. ④는 test까지 포함해서 계산하기 때문에 데이터 누수가 있어요.

## 실행 방법

Python 3 표준 라이브러리만 써요(numpy·sklearn 필요 없음). `<pkl 폴더>`는 pkl 3개를 둔 폴더예요. 아래 명령은 **프로젝트 최상위 폴더(`wf_project/`)에서** 실행해요.

```
python -I code/check_data.py <pkl 폴더>                          # 몇 분 걸려요
python -I code/explore.py    <pkl 폴더>
python -I -X utf8 code/features.py <pkl 폴더> features            # 약 2~3분, CSV 2개 생성
python -I -X utf8 code/eval_nearest_centroid.py features/features_mon.csv
```

## 지금까지 결과 (nearest centroid, 사이트 95개, test 1,900개)

우연히 맞힐 확률은 1/95 = 1.05%예요.

| 피처 조합 | 정확도 |
|---|---|
| 전체 55개 | 25.7% |
| 순서·집중도 (10개) | 25.5% |
| 버스트 (11개) | 17.5% |
| 시간 (18개) | 11.4% |
| 개수 (4개) | 10.2% |
| CUMUL (12개) | 8.2% |
| η² 상위 10개 (train 기준) | 10.7% |
| η² 상위 20개 (train 기준) | 9.7% |
| η² 하위 20개 (train 기준) | 15.3% |

- 아주 단순한 분류기인데도 우연(1%)보다 훨씬 높아서, 피처에 사이트 정보가 들어 있어요.
- η² 상위 20개가 하위 20개보다 정확도가 **낮아요**. 상위 피처끼리 같은 정보("기록 길이")를 반복해서 담고 있기 때문이에요. 피처를 고를 때 상관관계도 같이 봐야 해요.
- 강의에서 소개한 최신 기법(k-FP, CUMUL, DF)은 90% 이상이에요. 실제 모델(랜덤 포레스트, SVM, k-NN 등)은 모델링 단계에서 이 CSV로 학습하면 돼요.
