# open-world 실험 기록

open-world 실험의 설정, 데이터 문제와 해결, 피처 실험 결과를 정리한다. closed-world 실험은 [EXPERIMENTS.md](EXPERIMENTS.md)에 있다.

## 요약

| 항목 | 내용 |
|---|---|
| 문제 | mon 기록 95개 사이트 + unmon 기록(감시 대상이 아닌 사이트)을 섞어 놓고 "감시 대상인가"를 맞힌다 |
| 발견한 문제 | **mon과 unmon은 처음 14셀이 다르다.** 사이트와 무관한 수집 환경 차이다. 그대로 쓰면 ROC-AUC 1.0000이 나온다 |
| 해결 | **open-world 피처는 기록의 앞 14셀을 버리고 다시 계산한다** (`features_ow.py`). 버려도 closed-world 정확도는 그대로다(사이트 정보 0) |
| 방식 | 96클래스(사이트 95개 + unmon). 가장 높은 사이트 확률이 임계값 이상이면 감시 대상으로 판정. 이진 분류보다 낫다 |
| 후보 피처셋 | **`@all @early @bseq @dir50 @qconst` (134개, 앞 14셀 버린 피처)** |
| 결과 (RF, 기본 설정, train 내부 CV) | ROC-AUC **0.993**. unmon을 1%만 잘못 잡도록 임계값을 정하면 mon의 **91.4%**를 잡는다(사이트까지 맞힌 비율 90.6%) |
| 하지 않은 것 | 모델 선택·튜닝, 최종 임계값 결정, PR·ROC 그래프, test 평가 |

## 1. 설정

### 1.1 데이터와 라벨
| | 파일 | 라벨 | train | test |
|---|---|---|---|---|
| mon | `mon_standard.pkl` | 사이트 번호 0~94 | inst 0~17 (17,100개) | inst 18~19 (1,900개) |
| unmon | `unmon_standard10.pkl` | −1 | 9,000개 | 1,000개 |

- mon 분할은 closed-world와 같다.
- unmon은 기록마다 다른 사이트라서 무작위로 나눴다(시드 0). test의 unmon은 학습 때 보지 못한 사이트다.
- CV fold: mon = inst % 5, unmon = train 안 순번 % 5. **test는 쓰지 않았다.**
- 과제(intro_to_project.pdf 11·18쪽)에는 "감시 대상 = positive, 그 외 = negative"와 지표만 정해져 있다. 라벨·분할·방식은 위처럼 팀이 정했다.

### 1.2 두 가지 방식
| 방식 | 모델이 배우는 것 | 점수 |
|---|---|---|
| 이진 분류 | 감시 대상인가 아닌가 | 감시 대상일 확률 |
| **96클래스** | 95개 사이트 중 어느 것인가, 아니면 unmon인가 | 사이트 95개 중 가장 높은 확률 |

점수가 임계값 이상이면 감시 대상으로 판정한다. 임계값을 낮추면 더 많이 잡지만 잘못 잡는 것도 늘어난다.

### 1.3 지표
| 지표 | 뜻 |
|---|---|
| TPR | mon 중 감시 대상으로 판정한 비율 (많이 잡을수록 좋다) |
| FPR | unmon 중 감시 대상으로 **잘못** 판정한 비율 (낮을수록 좋다) |
| precision | 감시 대상으로 판정한 것 중 실제 mon 비율 |
| TPR_site | 96클래스에서 **사이트까지 맞힌** 비율. 다른 감시 사이트로 틀리면 오답 |
| ROC-AUC | 임계값 전체에 대한 요약 점수. 1.0이 완벽, 0.5는 찍기 |
| TPR@FPR1% | unmon을 1%만 잘못 잡도록 임계값을 정했을 때의 TPR. 실제 공격에서 중요한 값 |

- **주의 (비율)**: mon:unmon = 17,100:9,000으로 mon이 더 많다. 현실(감시 대상은 극소수)과 반대라서 precision이 실제보다 높게 나온다.
- **주의 (k-NN)**: k=5라 점수가 0, 0.2, …, 1.0 여섯 값뿐이다. unmon 중 1.0을 받는 것이 1%를 넘어서 TPR@FPR1%가 항상 0이다. 버그가 아니다. k-NN은 ROC-AUC로만 비교한다.
- **주의 (SVM)**: 확률 계산(`probability=True`)은 10배 이상 느려서 결정 함수 값을 점수로 쓴다. ROC-AUC와 TPR@FPR1%는 점수의 순서만 쓰므로 비교할 수 있다.

## 2. 데이터 문제: 처음 14셀이 mon과 unmon에서 다르다

### 2.1 발견
처음 실험(기존 피처 그대로)에서 ROC-AUC가 **1.0000**이었다(`logs/openworld_stage1.log`). 기본 55개 피처만으로는 0.968이었으므로 새로 넣은 앞부분 피처가 원인이었다.

| 셀 위치 | mon (19,000개) | unmon (10,000개) |
|---|---|---|
| 1~7 | 전부 `--+-+-+` | 전부 `--+-+-+` |
| **8** | **100% 송신(+)** | **99.98% 수신(−)** |
| 9~14 | 전부 수신 `------` | 기록마다 다름 (송신 비율 24~63%) |
| 15~ | 기록마다 다름 | 기록마다 다름 |

- **8번째 셀 방향 하나로 mon과 unmon이 99.99% 갈린다.**
- mon 안에서는 95개 사이트가 전부 같으므로 사이트 정보가 아니다. 웹페이지 내용이 오기 전 Tor 연결 준비 구간이고, **mon과 unmon을 서로 다른 환경(Tor 버전·설정 등)에서 수집한 흔적**으로 보인다. 수집 코드가 없어 확정할 수는 없다.
- 4b단계([EXPERIMENTS.md](EXPERIMENTS.md))에서 찾은 준상수 13개(`@qconst`)가 mon/unmon을 AUC 0.9999로 가른 것과 같은 현상이다.
- 실제 공격에서는 mon이든 unmon이든 같은 환경에서 접속하므로 이 차이는 쓸 수 없다. 그대로 두면 점수가 부풀려진다.

### 2.2 해결: 앞 14셀을 버리고 피처를 다시 계산
`code/features_ow.py`가 기록마다 앞 K셀을 지우고 기존 피처(55 + 150 + 171개)를 똑같이 다시 계산한다. 피처 이름은 그대로이고, 위치를 세는 피처(`first30_out`, `dir_001`, `bseq_4` 등)는 K+1번째 셀부터 센다.

- **K=14로 정한 근거**: mon은 1~14번째 셀이 19,000개 전부 같다(사이트 정보 0). 15번째부터 기록마다 달라진다.
- K=0으로 돌리면 기존 CSV와 같은 값이 나온다(반올림 차이 0.00005 이내). 추출 코드는 기존과 같다.

### 2.3 확인
**① 흔적이 사라졌나**: 피처 하나만으로 mon/unmon을 가르는 힘(단일 피처 AUC)의 최댓값

| 버린 셀 | 가장 잘 가르는 피처 |
|---|---|
| 0 | `bseq_6` 1.000, `dir_008` 1.000 |
| **14** | `first10_out` 0.692, `in_burst_1` 0.672 |
| 20 | `bseq_1` 0.784 (버스트 중간을 잘라서 생긴 값으로 보인다) |
| 30 | `first10_out` 0.656 |

14셀을 버리면 거의 완벽하게 가르는 피처가 없어진다. 남은 0.6~0.7은 사이트 종류가 달라서 생기는 정상적인 차이 수준이다.

**② 버린 구간에 사이트 정보가 있었나**: closed-world(mon끼리 비교)는 흔적의 영향을 받지 않으므로, 정확도 변화가 곧 사이트 정보의 손실이다 (RF, 134개, `logs/ow_skip_closedworld_check.log`)

| 버린 셀 | closed-world CV 정확도 |
|---|---|
| 0 | 95.56% |
| **14** | **95.67%** (손실 없음) |
| 30 | 91.22% (−4.3%p) |

- **앞 14셀에는 사이트 정보가 없다.** 버려도 잃는 것이 없다.
- **15~30번째 셀에는 사이트 정보가 있다.** 30셀을 버리면 open-world 점수도 떨어지는데(아래 ③), 흔적이 사라져서가 아니라 진짜 정보를 잃어서라고 보는 것이 맞다. 그래서 K=14를 쓴다.

**③ K를 바꿔도 결론이 같은가** (RF, 96클래스, `logs/ow_skip_sensitivity.log`)

| 조합 | K=14 AUC | K=14 TPR@FPR1% | K=30 AUC | K=30 TPR@FPR1% |
|---|---|---|---|---|
| `@all` (55) | 0.9852 | 84.1% | 0.9585 | 69.4% |
| `@all @early @bseq @dir50` (121) | 0.9903 | 89.2% | 0.9645 | 73.2% |
| `@all @early @bseq @dir50 @qconst` (134) | **0.9932** | **91.4%** | **0.9671** | **76.0%** |

K=30에서도 조합 간 순서가 같다. 피처 선택의 결론은 K에 따라 바뀌지 않는다.

### 2.4 closed-world에는 영향이 없다
closed-world는 mon끼리만 비교한다. mon은 앞 14셀이 전부 같아서 모델이 이 구간으로 사이트를 구분할 수 없다. closed-world는 기존 CSV를 그대로 쓴다.

## 3. 피처 실험

### 3.1 규칙 (실험 전에 정함)
| 항목 | 내용 |
|---|---|
| 피처 | 앞 14셀을 버린 피처 (`--skip 14`) |
| 방식 | 96클래스 (먼저 비교한 결과 이진 분류보다 좋았다. 아래 3.2) |
| 평가 | train 내부 5-fold CV의 out-of-fold 점수. **test는 쓰지 않는다** |
| 주 지표 | ROC-AUC. 보조 지표는 TPR@FPR1% |
| 판단 기준 | 기준 조합 대비 ROC-AUC 차이가 **fold 간 표준편차 이내면 같은 수준**, 피처가 적은 쪽을 고른다 |
| 모델 | k-NN, ET, RF, LR, SVM. 기본 하이퍼파라미터 (closed-world와 같음). **모델 순위가 아니라 피처 비교용이다** |
| 그룹 정의 | closed-world 4b단계 이후의 정의를 쓴다 (`@early` 6, `@bseq` 24, `@dir50` 36, 준상수 13개는 `@qconst`) |
| 재현 | `python -I -X utf8 code/run_ow_stages.py <단계> [svm\|nosvm]` → `logs/ow_stage*.log` |

RF의 fold 간 표준편차는 0.0007~0.0022, ET 0.0006~0.0037, LR 0.0014~0.0046, SVM 0.0031~0.0059, k-NN 0.0022~0.0061이다.

### 3.2 방식 비교: 이진 vs 96클래스
(RF, 앞 14셀 버림, 4b단계 이전 그룹 정의의 131개, `logs/openworld_stage2.log`)

| 방식 | ROC-AUC | TPR@FPR1% | TPR@FPR5% |
|---|---|---|---|
| 이진 분류 | 0.9869 | 74.8% | 92.6% |
| **96클래스** | **0.9917** | **89.6%** | **95.2%** |

96클래스가 낫고, 임계값을 엄격하게 잡을수록 차이가 커진다. 사이트마다 따로 배우는 것이 "감시 대상 전체"를 한 덩어리로 배우는 것보다 정확하다. 이후 실험은 96클래스로 한다. 시간 피처를 빼도 결과가 같았다(ROC-AUC 이진 0.9869 → 0.9869, 96클래스 0.9917 → 0.9916). 처음에 의심했던 "시간 피처가 환경 차이를 배운다"는 아니었다.

### 3.3 1단계: 기준점 (기본 55개, B)
| | k-NN | ET | RF | LR | SVM |
|---|---|---|---|---|---|
| ROC-AUC | 0.9045 | 0.9692 | 0.9852 | 0.8510 | 0.9133 |
| TPR@FPR1% | (0) | 79.6% | 84.1% | 20.7% | 12.9% |

앞 14셀을 버린 데이터에는 상수 피처가 없어서 기준점은 `@all` 55개 전체다(closed-world는 `in_burst_1~3`을 뺀 52개).

### 3.4 2단계: 빼도 되는 피처가 있나
| 조합 | 개수 | k-NN | ET | RF | LR | SVM | 결정 |
|---|---|---|---|---|---|---|---|
| B | 55 | 0.9045 | 0.9692 | 0.9852 | 0.8510 | 0.9133 | |
| B − 시간 그룹 | 37 | +0.024 | +0.005 | +0.002 | **−0.065** | −0.009 | 기각 |
| B, 길이 계열 → 1개 | 39 | +0.001 | +0.008 | +0.002 | −0.009 | +0.005 | 기각 |

closed-world 2단계와 같은 결론이다. 시간 피처는 트리 모델에는 필요 없지만 LR·SVM에는 필요하다. 빼서 크게 좋아지는 경우는 없다.

### 3.5 3단계: 새 피처를 더하면 좋아지나 (B에 추가)
| 조합 | 개수 | k-NN | ET | RF | LR | SVM |
|---|---|---|---|---|---|---|
| B | 55 | 0.9045 | 0.9692 | 0.9852 | 0.8510 | 0.9133 |
| B + @early | 61 | +0.020 | +0.007 | **+0.003** | +0.031 | **+0.024** |
| B + @cumulabs | 68 | +0.007 | +0.004 | +0.002 | +0.022 | +0.005 |
| B + @bseq | 79 | +0.003 | +0.005 | +0.002 | +0.044 | +0.022 |
| B + @dir50 | 91 | −0.008 | **+0.013** | +0.001 | +0.045 | +0.021 |
| B + @cumul100 | 155 | +0.003 | −0.015 | −0.006 | +0.021 | −0.035 |
| B + @bseqlong | 125 | −0.082 | −0.016 | −0.008 | +0.026 | (실행 안 함) |

- **@early, @bseq, @dir50, @cumulabs는 대부분의 모델에서 오른다.** closed-world와 같다. 기록 앞부분(15번째 셀 이후)의 방향 패턴이 open-world에서도 핵심이다.
- **@cumul100, @bseqlong은 트리 모델에서 떨어진다.** closed-world와 같다.

### 3.6 3b·3c단계: 조합
| 조합 | 개수 | k-NN | ET | RF | LR | SVM |
|---|---|---|---|---|---|---|
| B + @early + @bseq | 85 | 0.9166 | 0.9804 | 0.9905 | 0.9120 | 0.9450 |
| B + @early + @bseq + @dir50 | 121 | 0.9209 | 0.9863 | 0.9903 | 0.9346 | (실행 안 함) |
| 위 + @cumulabs | 134 | 0.9216 | 0.9867 | 0.9903 | (실행 안 함) | (실행 안 함) |
| closed-world 후보 그대로 (`@all -@const @early @bseq @dir50`) | 118 | 0.9104 | 0.9783 | **0.9739** | (실행 안 함) | (실행 안 함) |
| B + @early + @bseq + `@qconst` 중 4개 | 89 | 0.9325 | 0.9871 | 0.9921 | 0.9366 | |
| **B + @early + @bseq + @dir50 + @qconst** | **134** | **0.9587** | **0.9922** | **0.9932** | **0.9664** | **0.9683** |

(`@qconst` 중 4개 = `first10_out`, `bseq_4~6`. SVM은 한 번에 약 9분이 걸려 일부만 돌렸다. "실행 안 함"은 세션이 끝나 중단된 것이다)

**closed-world 후보(118개)를 그대로 쓰면 안 된다.** RF가 0.9903 → 0.9739로 떨어진다. 차이는 `in_burst_1~3` 3개뿐이다. closed-world에서는 상수라 뺐지만, 앞 14셀을 버린 데이터에서는 "흔적 구간 직후의 첫 수신 버스트 길이"를 뜻하고 open-world에서 중요하다(14셀 버린 데이터에서 단일 피처 AUC 2위).

**`@qconst` 13개를 다시 넣으면 모든 모델에서 오른다** (121개 대비 RF +0.003, ET +0.006, k-NN +0.038, LR +0.032, 모두 fold 표준편차의 2배 이상. SVM은 85개 대비 +0.023).
- `@qconst`는 원래 데이터에서 앞 14셀의 흔적을 담은 피처라 closed-world 그룹에서 뺐다(4b단계).
- 앞 14셀을 버린 데이터에서는 같은 이름이 **15번째 셀 이후**를 가리킨다(`first10_out` = 15~24번째 셀 중 송신 수, `dir_006~014` = 20~28번째 셀 방향). 흔적 구간이 아니고, 상수도 아니다.
- 따라서 open-world에서 쓰는 것은 4b단계가 걱정한 "환경 차이로 부푼 점수"가 아니다. 위 2.3의 확인(단일 피처 AUC 최대 0.69, closed-world 정확도 손실 없음)이 근거다.
- 이름이 "준상수"라 헷갈리므로 open-world 문서·보고서에서는 "15~28번째 셀 구간의 피처"로 설명하는 것이 좋다.

### 3.7 결정
- **open-world 후보 피처셋: `@all @early @bseq @dir50 @qconst` (134개, 앞 14셀을 버린 피처).**
  - 명령: `python -I -X utf8 code/openworld.py @all @early @bseq @dir50 @qconst --skip 14 --mode multi`
  - 앞 14셀을 버리지 않은 기존 피처의 "131개(4b 이전 후보) + `in_burst_1~3`"과 이름 구성이 같다.
- **RF 기준: ROC-AUC 0.9932, TPR@FPR1% 91.4% (사이트까지 맞힌 비율 90.6%), precision 99.4%.**
- closed-world 후보(118개)와 피처셋이 다르다. 4b단계의 결정("모델·과제마다 피처셋을 따로 정한다")과 맞다.

- [ ] PR·ROC 곡선 그래프 (과제 지표)
- [ ] test로 최종 1회 평가 (`--test`)
- [ ] mon:unmon 비율이 현실과 반대인 점을 보고서 한계에 적기. 필요하면 unmon 비율을 바꿔 precision 변화를 보여주기
