# 점수 정리: 지금 점수는 무엇이고, 최종 점수는 어떻게 내나

이 문서는 "지금 나와 있는 점수가 무슨 의미인지"를 쉽게 정리한 것이다. 실험 과정은 [EXPERIMENTS.md](EXPERIMENTS.md), [OPENWORLD.md](OPENWORLD.md)에 있다.

## 한눈에 보기

- **아직 튜닝을 안 했다.** 모든 모델은 기본 설정 그대로다. 바꾼 것은 피처와 전처리뿐이다.
- **아직 최종 점수(test 점수)가 없다.** 지금 있는 숫자는 전부 "모의고사 점수(CV)"다.
- **최종 점수는 튜닝이 끝난 뒤 test로 딱 한 번 잰다.** 그 값이 보고서에 들어간다.
- **최종 점수는 지금 점수보다 낮게 나올 가능성이 크다.** test에 들어간 마지막 방문(inst 19) 기록이 유독 짧고 느리기 때문이다.

---

## 1. 데이터를 어떻게 나눴나

### mon (감시 대상 95개 사이트)

- 사이트 95개 × URL 10개 × 방문 20번 = **19,000개 기록**
- 방문 번호(inst)는 0~19다. 같은 URL을 20번 방문한 순서다.

| 용도 | 방문 번호 | 개수 |
|---|---|---|
| **train** (공부용) | inst 0~17 | 17,100개 |
| **test** (최종 시험용) | inst 18~19 | 1,900개 |

모든 URL이 train과 test에 다 들어 있다. "본 적 있는 사이트를 새로 방문했을 때 맞히는가"를 재는 구조다.

### unmon (감시 대상이 아닌 사이트, open-world에서만 사용)

- **10,000개 기록**, 기록마다 다른 사이트다.
- 무작위로 나눴다(시드 0): **train 9,000개, test 1,000개**
- test의 unmon 1,000개는 학습 때 한 번도 못 본 사이트다.

### train 안을 다시 5조각으로 (CV용)

train을 방문 번호로 5조각으로 나눈다(inst를 5로 나눈 나머지). 예를 들어 조각 0은 inst 0, 5, 10, 15다. unmon은 train 안의 순서대로 5조각으로 나눈다.

## 2. 점수는 두 종류다: 모의고사(CV)와 수능(test)

| | CV 점수 (모의고사) | test 점수 (수능) |
|---|---|---|
| 무엇으로 채점 | train을 5조각으로 나눠서, 4조각으로 공부하고 1조각으로 채점. 이걸 5번 돌려 평균 | 처음부터 따로 빼 둔 test |
| 언제 | 피처·설정·모델을 고르는 동안 계속 | 모든 선택이 끝난 뒤 **딱 한 번** |
| 무엇에 쓰나 | 고르기용 | 보고서용 |
| 지금 있나 | 있다 (아래 3·4절의 숫자 전부) | **없다** |

### 왜 test를 미리 보면 안 되나

test 점수를 보면서 피처나 설정을 고르면, 진짜 좋은 조합 대신 **test 1,900개에 우연히 잘 맞는 조합**을 고르게 된다. 그러면 마지막 test 점수가 실제 실력보다 부풀어 있다. 수능 문제를 미리 보고 공부 방법을 고른 다음 같은 수능으로 실력을 재는 것과 같다. 이것을 "test에 과적합한다" 또는 "누수"라고 한다.

### 그럼 train으로 채점하면 되지 않나

학습한 데이터로 그대로 채점하면 외운 것도 맞혀 버린다(RF는 거의 100%가 나온다). 그래서 CV는 **매번 학습에 안 쓴 조각으로 채점**한다. 외운 걸로는 점수가 안 나온다.

### CV의 장점이 하나 더 있다

점수가 5개 나오므로 **얼마나 흔들리는지**(표준편차)를 볼 수 있다. "0.3%p 차이가 진짜인지 우연인지"를 판단할 수 있다.

### CV도 약간은 낙관적이다

CV 점수를 보면서 수십 개 조합 중 가장 좋은 것을 골랐으므로, 고른 조합의 CV 점수는 실제보다 조금 높을 수 있다. 그래서 최종 확인은 test로 한다.

## 3. closed-world 점수 (95개 사이트 중 어느 것인가)

**조건**: 후보 피처 131개, 기본 설정(튜닝 안 함), train 내부 CV, 점수 = 정확도

| 모델 | CV 정확도 | 흔들림 (fold 간 표준편차) | 메모 |
|---|---|---|---|
| ET | **95.8%** | ±0.2%p | |
| RF | **95.7%** | ±0.4%p | |
| SVM | 95.3% | ±0.5%p | 그룹 가중치(`--gw`)를 켠 값. 끄면 94.9% |
| k-NN | 91.9% | ±0.8%p | 그룹 가중치를 켠 값. 끄면 90.4% |
| LR | 90.0% | ±0.9%p | 그룹 가중치를 켜면 오히려 88.1%로 떨어져서 끈 값 |

> ⚠ 모두 기본 설정이라 **모델 순위가 아니다.** SVM·k-NN은 튜닝하면 더 오를 수 있다.

### 피처를 바꾸면서 점수가 어떻게 올랐나 (RF 기준, CV)

| 피처셋 | 개수 | RF CV 정확도 |
|---|---|---|
| 처음 만든 피처 (상수 3개 제외) | 52 | 87.9% |
| + 앞부분 방향 패턴 (`@early`, `@bseq`) | 82 | 95.5% |
| + 누적합 고정 위치 + 처음 50셀 방향 (**지금 후보**) | 131 | 95.7% |

가장 큰 변화는 **기록 앞부분의 방향 패턴**을 넣었을 때다(+7.6%p). 그 뒤로는 0.2~0.4%p 수준의 작은 개선이다.

## 4. open-world 점수 (감시 대상인가 아닌가)

**조건**: 후보 피처 134개(앞 14셀 버림), RF 기본 설정, 96클래스 방식(사이트 95개 + unmon), train 내부 CV

### 먼저 용어

모델은 기록마다 "감시 대상일 가능성" 점수를 낸다. 이 점수가 기준(임계값)보다 높으면 "감시 대상"으로 판정한다. 기준을 낮추면 많이 잡지만 오탐도 늘고, 높이면 반대다.

| 용어 | 쉬운 뜻 |
|---|---|
| TPR | 감시 대상(mon)을 감시 대상으로 **잡은** 비율. 높을수록 좋다 |
| FPR | 감시 대상이 아닌 것(unmon)을 감시 대상으로 **잘못 잡은** 비율. 낮을수록 좋다 |
| precision | "감시 대상"이라고 판정한 것 중 **진짜** 감시 대상의 비율 |
| ROC-AUC | 기준을 어떻게 잡든 전체적으로 얼마나 잘 가르는지. 1이 완벽, 0.5는 찍기 |

### 점수

| 지표 | CV 값 |
|---|---|
| ROC-AUC | **0.993** |
| 오탐을 1%로 맞췄을 때 TPR | **91.4%** (사이트까지 맞힌 비율 90.6%) |
| 이때 precision | 99.4% |

### 기준(오탐 허용치)에 따라 달라지는 점수

팀이 "오탐을 몇 %까지 허용할지" 정해야 최종 보고 숫자가 정해진다.

| 오탐 허용치 (FPR) | 감시 대상을 잡는 비율 (TPR) | 사이트까지 맞힘 | precision |
|---|---|---|---|
| 0.1% | 79.8% | 79.7% | 99.9% |
| 0.5% | 87.7% | 87.2% | 99.7% |
| **1%** | **91.4%** | **90.6%** | **99.4%** |
| 5% | 96.0% | 94.1% | 97.4% |
| 10% | 97.9% | 95.2% | 95.1% |

### precision 99%는 믿으면 안 된다

지금 데이터는 mon이 unmon보다 많다(17,100 : 9,000). 현실에서는 감시 대상이 아닌 사이트가 훨씬 많다. 같은 모델이라도 unmon이 많아지면 precision이 크게 떨어진다.

| 오탐 허용치 | 지금 데이터 비율 (1.9 : 1) | 1 : 1 | 1 : 10 | 1 : 100 |
|---|---|---|---|---|
| 0.1% | 99.9% | 99.9% | 98.8% | 88.9% |
| 1% | 99.4% | 98.9% | 90.2% | **48.0%** |
| 5% | 97.4% | 95.1% | 66.1% | 16.3% |

unmon이 100배 많으면, 오탐 1%에서도 "감시 대상"이라고 판정한 것의 **절반이 오탐**이다. 보고서의 한계로 쓴다.

## 5. 최종 점수는 왜 더 낮게 나올까

test로 빼 둔 마지막 방문(inst 18~19), 특히 **inst 19가 다른 방문과 다르다.**

| | inst 0~17 | inst 18 | inst 19 |
|---|---|---|---|
| 길이 중앙값 | 약 3,300~3,500셀 | 3,184셀 | **2,340셀** |
| 지속 시간 중앙값 | 약 22~26초 | 29.9초 | **40.7초** |

![방문 순서별 길이·지속 시간](../figures/data_by_inst.png)

inst 19는 더 짧고 느리다. 네트워크가 느렸거나 페이지 로딩이 덜 끝난 것으로 보인다(수집 코드가 없어 확정은 못 한다). 모의고사보다 수능이 유독 어렵게 나온 셈이다.

**예전 예시**: 처음 만든 피처 55개의 RF로 CV는 약 88%였는데 test는 약 73%였다.

### 팀이 정해야 할 것: test를 어떻게 둘까

| 선택지 | 장점 | 단점 |
|---|---|---|
| (a) 지금처럼 inst 18~19 | "환경이 바뀌어도 버티는가"까지 평가한다 | 점수가 낮게 나온다 |
| (b) 방문마다 골고루 뽑아 다시 나눔 | 일반적인 성능을 보여 준다. CV와 비슷하게 나올 것이다 | 다시 나눠야 한다 |

어느 쪽이든 **튜닝 전에** 정하고, 고른 이유를 보고서에 쓴다.

## 6. 앞으로의 순서

1. **팀 결정**: test 분할(5절), open-world 오탐 허용치(4절)
2. **튜닝** (7단계, 모델 담당): 모델 설정값을 CV로 맞추고 최종 모델을 고른다. **test는 아직 안 본다**
3. **최종 평가** (8단계): 고른 모델로 test를 **딱 한 번** 돌린다. open-world는 CV로 정한 기준(임계값)을 그대로 쓴다
4. 보고서에는 test 점수를 쓰고, CV 점수는 "모델을 고를 때 쓴 점수"로 함께 적는다

### 점수를 다시 내는 명령

```
python -I -W ignore -X utf8 code/experiment.py @all -@const @early @bseq @cumulabs @dir50 -m rf              # closed-world CV
python -I -W ignore -X utf8 code/experiment.py @all -@const @early @bseq @cumulabs @dir50 -m knn --gw        # k-NN (그룹 가중치)
python -I -W ignore -X utf8 code/openworld.py @all @early @bseq @dir50 @qconst --skip 14 --mode multi        # open-world CV
```

`--test`를 붙이면 test로 채점한다. **최종 1회에만 쓴다.**
